إذا ظهرت قاعدة (default)، استخدمها كما هي.

اختبر قواعد الوصول قبل نشر الموقع

الاختبار محلي على مشروع تجريبي؛ لا يغيّر بيانات طلابك.

٢. انسخ الأمر الطويل كاملًا من هذا الدليل ونفّذه كسطر واحد.

أنشئ حسابك وأكّد بريدك، ثم انسخ UID

حساب المدير في التطبيق له بريد وكلمة سر؛ صلاحية الإدارة تُربط بمعرّف UID الخاص به.

١. سجّل الدخول بحسابك، أو أنشئه إن لم يكن موجودًا.

٢. أكّد البريد من الرسالة، ثم اضغط «أعد التحقق».

٣. في Firebase افتح Authentication → Users.

٤. ابحث عن بريدك وانسخ User UID.

ظهور رسالة «البريد غير مضاف» قبل تهيئة الإدارة أمر متوقع.

امنح حسابك صلاحية المدير مرة واحدة

هذه أهم خطوة: اسم المجموعة ثابت، ومعرّف المستند هو UID حسابك الحقيقي.

١. افتح Firestore → Data → Start collection.

٢. اسم المجموعة: oliveFreeAdmins، ثم اضغط Next / التالي.

٣. Document ID: الصق UID حسابك، وليس البريد.

٤. أضف enabled من نوع boolean بقيمة true ثم احفظ.

لا تكتب true كنص، ولا تمنح هذه الصلاحية لحساب طالب.

افتح لوحة الإدارة وأضف إيميلات الطلاب

أعد تحميل الموقع بعد منح الصلاحية، ثم افتح لوحة الإدارة من القائمة أو قائمة الحساب.

١. افتح صفحة لوحة الإدارة.

٢. اكتب إيميل الطالب واضغط «إضافة إلى القائمة».

٣. يفتح الطالب حسابه ويؤكد ملكية بريده.

٤. أضف أيضًا إيميلات أصحاب الحسابات القديمة.

حد الجهازين إرشادي داخل الواجهة. تعطيل السماح للإيميل يمنع وصول الحساب إلى بياناته عبر قواعد Firestore.

لقطة فعلية لواجهة التطبيق من المحاكي المحلي؛ جميع بياناتها تجريبية، وليست من حسابك
إعداد الأستاذ محمود بركاتSpark · دون Cloud Functions · دون وسيلة دفع
ملاحظات قبل البدء

لم ينشر هذا الدليل أي تغييرات على مشروعك. الحصص المجانية محدودة، وقد تتوقف بعض الطلبات عند بلوغها. قائمة الإيميلات وعزل بيانات الحسابات يعتمدان على قواعد Firestore؛ حد الجهازين إرشادي داخل التطبيق وليس منعًا تقنيًا صارمًا. إنشاء حساب Authentication لا يعني السماح له بفتح الدروس.

إذا سبق أن نشرت وظائف النسخة المدفوعة أو فعّلت Blaze، راجع إيقافها وخطة المشروع وفق الدليل النصي؛ رفع هذه الملفات وحده لا يحذف خدمات مدفوعة موجودة.
